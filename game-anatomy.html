游戏文件解剖

这页讲什么游戏本体的文件全被打包在档案里，硬盘上看不到。这页拆开包装，讲清里面分几层、每层放什么。

你需要装了重制版的电脑，加一个 CASCView（下载见下）。

读完你会会用工具导出任意文件；知道改动该放哪个目录；能让改动生效而不碰本体。

本页目录

    两代档案格式：MPQ 与 CASC

    游戏文件不在硬盘上散着放，而是打包进档案（archive）。1.30 之前用 MPQ，之后换成 CASC。

    档案格式从哪版起形态
    MPQ1.30 前多个独立包，按补丁与语言拆开
    CASC1.30 起所有资源统一存进一个 CASC 存储，不再按补丁拆包

    不管哪一代，游戏找文件的顺序都是固定的：从上往下找，上面有同名文件就用上面的。

    这也是「启用本地文件」能覆盖游戏数据的原因——它把自己放进了最上面一层。

    MPQ 时代的多包覆盖　老版本把内容拆在几个包里，读的时候按 war3patch.mpq → war3xlocal.mpq → war3x.mpq → war3local.mpq → war3.mpq 逐层回退：补丁包级别最高，x 为冰封王座专用，local 为语言层。此外每张地图还会额外加载一个地形包（如 A.mpq）。重制版把这些层压成了一个 CASC 存储。

    工具：CASCView

    看 CASC 用 Ladislav Zezula 的 CASCView（免费）。看旧版 MPQ 用同一家的 MPQ Editor。

    1. 从 zezula.net 的 CASCView 页面下载并运行，选菜单 Storage → Open Storage（打开存储）。
    2. 选中游戏根目录（含 .build.info 的 Warcraft III\_retail_\），等它认出 CASC 存储。
    3. 展开左侧 war3.w3mod 等节点，右键 Extract / Export（导出）取走单个文件或整个目录。
    两点先记住　① 文件树里到处出现的 .w3mod 后缀只是虚拟层目录名，不是真实文件夹；② CASCView 只读，要改文件得先导出，再走文末的本地文件流程。

    安装目录速览

    战网装出来的目录结构如下。只有 _retail_\ 里才是游戏本体，工具和本地文件都指向它。

    路径说明
    Warcraft III\战网安装目录，正式版与 PTR 的游戏根并列于此
    _retail_\游戏根（PTR 为 _ptr_\），工具与本地文件都指向这里
    .build.info记录构建版本与 CASC 指纹，CASCView 靠它定位
    Data\CASC 存储本体，全为二进制，不必手拆，交给工具
    data\分包文件 *.bin，游戏数据的主体
    config\存储配置
    indices\索引，记录文件名与分包位置的对应关系
    dbcache\本地数据库缓存
    x86_64\64 位客户端目录，游戏与编辑器主程序都在这里
    Warcraft III.exe游戏主程序
    World Editor.exe世界编辑器主程序，汉化补丁作用的对象
    Warcraft III.exe启动器，负责拉起 x86_64\ 下的主程序

    CASC 分层结构

    CASC 内部不是一个大文件夹树，而是多个根目录叠在一起。下面按优先级从高到低排，同名文件谁在上面谁生效。

    先看一个例子　同一个路径 units\human\footman\footman.mdx 在基础层放的是 SD 模型，在 _hd.w3mod 放的是 HD 模型。开高清时用 _hd.w3mod 那份，切回经典才落到基础层那份。
    层放什么
    _Balance\数据集覆盖层：slk 与 *Func.txt 各一套，即编辑器里选得到的数据集
    Melee_V0\对战（近战）数据集
    Custom_V0\自定义数据集的基线版本
    Custom_V1.w3mod\自定义数据集的最新版本
    _hd.w3mod\重制版（HD）模型与贴图，贴图多为 .dds
    _de.w3mod\决定版（Definitive Edition）图标与美术
    _tilesets\按地形组覆盖的 HD 资源
    *.w3mod\每个地形组一个包（洛丹伦的夏天、卡利姆多……）
    _locales\语言覆盖层，每种语言一个包
    <语言>.w3mod\串表、UI 文本、字体与配音
    _teen.w3mod\青少年模式（低暴力）资源
    _deprecated.w3mod\为兼容保留、实际已弃用的文件
    war3.w3mod\基础层：SD 美术、对象数据、脚本，以及下节那张目录表
    怎么用这张表　想改的某个文件在哪一层，就在哪一层改；上层只放「改动过的文件」，没改的不必镜像一份。

    war3.w3mod 目录速查

    基础层的一级目录 21 个。二级目录的组织主线只有三条：模型按「种族 / 地形组」分文件夹，每个素材再单占一个目录；对象数据与 slk 表放在各目录根；贴图大多平铺。

    目录放什么
    abilities\技能特效与弹道模型，分两个子目录
    spells\技能特效模型，按「种族 → 技能」两层组织
    <种族>\human / orc / undead / nightelf / demon 等
    <技能>\每个技能一个目录，内含该技能的特效模型
    weapons\<弹道>\投射物 / 弹道模型，每个弹道一个目录
    buildings\建筑模型
    <种族>\<建筑>\每个建筑一个目录，按种族分
    campaign\官方战役地图，按战役 / 章节分文件夹
    doodads\装饰物模型
    <地形组>\lordaeronsummer / ashenvale / northrend 等
    <类别>\structures / plants / props
    <名称>\每个装饰物一个目录，内含模型与贴图
    environment\环境模型、植被；无子目录，按素材名平铺
    fonts\字体；.ttf 直接平铺在此层
    maps\对战与遭遇战地图
    movies\过场动画；.mp4 直接平铺在此层
    objects\杂项对象模型；除下列目录外，其余素材按名称平铺
    inventoryitems\<物品>\可拾取物品模型，每个物品一个目录
    pathtextures\通行判定贴图，用于寻路与建造
    replaceabletextures\可替换贴图：图标、选择圈、悬崖、团队色
    commandbuttons\技能 / 物品的亮图标（BTN*.blp）
    commandbuttonsdisabled\对应的暗图标（DISBTN*.blp），用于冷却与不可用态
    selection\选择圈、施法范围圈
    cliff\悬崖贴图
    teamcolor\团队色蒙版
    scripts\JASS 公共库与 AI 脚本
    ai\AI 脚本
    shaders\着色器；无子目录，文件平铺
    sharedmodels\共享杂项模型：烟雾、羽毛、光晕等
    sound\单位语音、界面音、音乐、环境音
    units\单位语音，按「种族 → 单位」两层组织
    <种族>\human / orc / undead / nightelf / creeps 等
    <单位>\每个单位一个目录，内含选中、移动、攻击等语音
    interface\界面提示音，含 warning\ 等
    music\mp3Music\背景音乐
    ambient\环境音
    splats\地面贴花与闪电数据
    terrainart\地形贴图与地形 slk
    <地形组>\按地形组划分，文件名形如 <缩写>_<地块>.blp
    textures\贴图，以 .blp 为主；无子目录，基本平铺
    ui\界面资源
    framedef\.fdf 框架定义
    glues\主菜单等界面
    console\控制台皮肤
    units\单位模型与对象数据
    <种族或类别>\human / orc / undead / creeps / critters 等
    <单位>\每个单位一个目录，内含 .mdx 模型与贴图
    webui\1.32+ 的网页化前端资源
    baseframes\界面框架的网页资源

    路径不区分大小写。上表以经典（SD）层为准，_hd.w3mod / _de.w3mod 层的目录会多出一些、少一些。

    核心数据文件：SLK 与 INI 串表

    单位、技能、物品、科技的「对象数据」不是存在一个文件里，而是由三类纯文本拼合：slk 管数值，Func 管按钮与快捷键，Strings 管显示文本。改数据、做对照都绕不开它们。

    SLK 表：数值字段

    units\ 与 _Balance\*.w3mod\units\ 下的 .slk 是类 SYLK 电子表格文本。一行形如 C;X列;Y行;K"值"，首列 ID 决定是哪个对象。

    • UnitData.slk：单位杂项数据
    • UnitBalance.slk：单位属性与平衡值
    • UnitUI.slk：单位界面字段
    • UnitWeapons.slk：单位武器数据
    • AbilityData.slk：技能数据
    • ItemData.slk：物品数据
    • UpgradeData.slk：科技升级
    • DestructableData.slk：可破坏物

    *Func.txt：补充字段

    同目录下的 HumanUnitFunc.txt、CommonAbilityFunc.txt、ItemFunc.txt 这类文件是 INI 风格的补充字段，放按钮位置、快捷键、图例引用这些 slk 装不下的东西。

    *Strings.txt：显示文本

    名称与提示文本按种族 / 类别分文件，集中在语言层 _locales\<语言>.w3mod\units\ 下，如 humanunitstrings.txt、commonabilitystrings.txt、itemstrings.txt。格式是 INI，以对象 ID 为节：

    [AHtb]
; 山丘之王 —— 风暴之锤（节选，有删改）
Name=风暴之锤
Tip=风暴之锤(|cffffcc00T|r)
Ubertip=掷出一把魔法之锤，对目标造成伤害并使其眩晕。

    常用键：Name（名称）、Tip（按钮提示）、Ubertip（详细说明）、Hotkey、EditorSuffix。文本里的 |cAARRGGBB … |r 是内联颜色标记。

    本站汉化词条表与补丁说明的专名，就是拿 zhcn.w3mod 与 enus.w3mod 两套 Strings 逐 ID 对照核出来的。

    ui\ 目录：编辑器与界面

    编辑器的行为数据放在基础层 ui\，显示文本在语言层 _locales\<语言>.w3mod\ui\，框架文本含 globalstrings.fdf 等。汉化补丁改的主要就是这批文件。

    • triggerdata.txt：触发 GUI 的事件 / 动作 / 参数结构
    • triggerstrings.txt：对应的显示文本
    • worldeditdata.txt：菜单与对象编辑器字段
    • worldeditstrings.txt：编辑器界面文本
    • aieditordata.txt：AI 编辑器数据
    • framedef\*.fdf：界面框架定义

    地图文件（.w3m / .w3x / .w3n）

    地图也是档案包，格式与游戏本体分家了：.w3m 是原版（混乱之治）地图，.w3x 是冰封王座地图，.w3n 是战役包，本质都是带 512 字节头部的 MPQ 容器。

    游戏本体已改用 CASC，地图却至今仍是 MPQ——所以拆地图一律用 MPQEditor，不必碰 CASC。包里 war3map.* 家族的逐个详解见姊妹篇：

    → 地图文件解剖：用 MPQEditor 拆开地图包 地形、物编七件套、触发、字符串表，逐个文件讲格式与作用，附加密手法对照。

    .dds现代贴图格式_hd.w3mod\、_de.w3mod\ 层

    .fdf / .tocUI 框架定义 / 框架载入清单ui\framedef\
    .mp4视频movies\

    启用本地文件（Allow Local Files）

    游戏默认只读地图和 CASC。打开「本地文件」后，读取顺序变成「本地文件 > 地图 > CASC 各层」：把文件按有效路径放进游戏根目录，游戏就优先加载你的版本。

    注意层级上限　本地文件整体只是最上面的一个图层，不能像 CASC 里的 _hd.w3mod、_locales 那样拆成多层互相叠放。

    第一步：改注册表

    在 HKEY_CURRENT_USER\Software\Blizzard Entertainment\Warcraft III 下新建 DWORD (32 位) 值，名称 Allow Local Files，数值 1。三种做法任选其一：

    • 现成文件：运行本站编辑器汉化补丁附带的 AllowLocalFiles.reg；
    • 自建文件：新建文本文档，粘贴下面内容，另存为 allow.reg 后双击导入；
    • 命令行：reg add "HKCU\Software\Blizzard Entertainment\Warcraft III" /v "Allow Local Files" /t REG_DWORD /d 1
    Windows Registry Editor Version 5.00

[HKEY_CURRENT_USER\Software\Blizzard Entertainment\Warcraft III]
"Allow Local Files"=dword:00000001

    关闭同理：值改回 0 或删掉该值。游戏根目录的位置：1.32.7 起是安装目录下的 _retail_\（PTR 为 _ptr_\），更早的版本直接就是安装目录。

    第二步：按有效路径放文件

    放进游戏根目录时，路径要砍掉层前缀（war3.w3mod\、_locales\zhcn.w3mod\ 这类），只留层内那一段：

    • war3.w3mod\units\human\peasant\peasant.mdx → _retail_\units\human\peasant\peasant.mdx（换农民模型）
    • _locales\zhcn.w3mod\ui\WorldEditStrings.txt → _retail_\ui\WorldEditStrings.txt（编辑器汉化补丁即由此生效）

    两个典型玩法

    • 画面 MOD　把改好的模型与贴图按原目录结构放进 _retail_\（units\、buildings\、textures\ 等），覆盖同名文件。
    • 字体 MOD　把字体文件放进 _retail_\fonts\，覆盖 war3.w3mod\fonts\ 下的同名文件。
    风险　本地文件在联机时同样生效，改动可能被对战平台判为作弊。请勿带着本地文件改动进对战。
